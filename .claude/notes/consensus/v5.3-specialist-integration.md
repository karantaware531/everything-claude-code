# Consensus: Specialist Government (v5.3)

## Decision

Adopt the **84 voltagent specialists** (already installed globally at
`~/.claude/plugins/cache/voltagent-subagents/`) as the **expert worker layer**
under our existing 22-agent governance. Voltagents do the work; our 22 agents
govern. No duplication, no overwriting.

## Council verdicts (4 advisors, isolated context)

### Architect — long-term correctness
**Adopt by reference, not copy.** Voltagents are versioned (1.0.2–1.0.3),
maintained upstream, auto-loaded by Claude Code. Copying files into
`.claude/agents/` fossilises them; referencing them keeps upgrades free. Our
architecture stays clean: governance (22 agents) + knowledge (Graphify) +
specialist pool (84 voltagent + 7 gitnexus + 1 graphify).

### Skeptic — what could go wrong
**Risk: orphan calls.** If a voltagent plugin is uninstalled, calls break.
**Mitigation:** SPECIALISTS.md lists expected specialists; `test_runner`
check 39 verifies plugin presence. If a specialist is missing, fall back
to our generic `code_agent` or `research_agent` with a logged warning.

### Pragmatist — ship speed
**Zero-cost win.** The plugins are already installed. We can see all 84 in
the available-skills list right now (voltagent-qa-sec:accessibility-tester,
voltagent-data-ai:ai-engineer, etc.). The only work is **documenting the
routing map** so orchestrator/planner/critic know when to delegate. No file
copies, no new packages, no policy changes.

### Critic — hidden costs
**Don't cut our 22.** Tempting to replace `critic` with voltagent's
`code-reviewer` or `reflection` with an external analyst. Reject. Our 22
are **architectural invariants** with opinions baked in (values_check,
Karpathy invariant, tier escalation, consensus compounding). Voltagents
are generic experts. Mixing these roles destroys the governance layer.

## Synthesis

3 of 4 advisors agree: **ADOPT BY REFERENCE**. Critic's concern is honored
by keeping the 22-agent governance layer intact.

## Approved actions

1. **KEEP all 22 of our agents** (no deletions) — they govern, not work.
2. **DOCUMENT 84 voltagent specialists** in `.claude/SPECIALISTS.md` — task-type → specialist map.
3. **UPDATE `orchestrator.md`** — route domain-specific work to voltagent:X before falling back to code_agent.
4. **UPDATE `critic.md`** and **`evaluator.md`** — remain our governance layer; do NOT delegate to voltagent:code-reviewer.
5. **COPY useful auxiliary content**:
   - `commit-commands` (3 commands) → `.claude/commands/` for git hygiene.
   - `claude-md-improver` skill → reference only (already loaded globally).
6. **ADD test_runner check 39**: voltagent plugin presence (non-fatal warning if uninstalled).
7. **CONSTITUTION v5.3**: new §35 documents the specialist government pattern.

## Rejected

- Copying voltagent agent files into `.claude/agents/`. REJECTED — fossilises versions, loses upstream updates, bloats repo.
- Replacing `critic` with voltagent:code-reviewer. REJECTED — loses values_check + uncertainty emission.
- Replacing `research_agent` with voltagent:research-analyst. REJECTED — research_agent has Graphify query integration built in.
- Copying `security_reminder_hook.py`. REJECTED — `/tmp/` path fails on Windows; our policy_guard + gateguard cover the threat model.
- Copying superpowers commands (brainstorm, write-plan, execute-plan). REJECTED — upstream marked deprecated.

## Reopen conditions

- Voltagent plugin uninstalled → re-examine whether to vendor affected specialists.
- A specific voltagent pattern consistently outperforms our governance agent → amend the affected agent via `registry_manager` (do not replace).
- New specialist category emerges (e.g. hardware engineering) → extend SPECIALISTS.md routing map.
