# Consensus: v5.5 Lead Agent + Consensus Government

## Decision

Five structural changes, unanimous Council approval:

1. **Constitution diet** — reduce `.claude/CLAUDE.md` from 725 to ~200 lines per Anthropic best practice.
2. **Orchestrator retired** — main Claude Code session IS the Lead Agent (per Agent Teams protocol). Routing logic moved to `.claude/rules/routing.md`.
3. **Consensus Council formalized** — 5 governance agents (critic, evaluator, security, reflection, knowledge_validator) have explicit ship veto; documented in constitution §5.
4. **Agent Teams enabled** — `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` in `settings.json` env.
5. **Default permission mode → acceptEdits** — Council + 6 safety layers + hook stack remove the need for per-edit approval.

## Council verdicts

### Architect
Constitution diet is correct. 725 lines breaks Anthropic's <200 guideline and
dilutes signal. Moving versioned changelog + evolution narratives to
`agentic-os-history.md` preserves the audit trail without context bloat.
Agent Teams enable IS the natural destination of our orchestrator — the
main session already plays that role informally; making it formal removes a
redundant subagent layer.

### Skeptic
Risks: (1) retiring orchestrator breaks any caller that hard-coded its name.
Mitigation: global search — only `AGENTS.md` and `CLAUDE.md` references,
both updated in this change. (2) `acceptEdits` bypasses per-edit approval;
if Council validation is skipped, damage is fast. Mitigation: critic + evaluator
are MANDATORY on every non-trivial output; hooks (gateguard + security_reminder +
policy_guard) still fire regardless of permission mode. (3) 200-line constitution
loses content. Mitigation: history.md preserves every deleted narrative;
constitution points to it.

### Pragmatist
High-ROI change. Constitution diet saves ~2,500 tokens per session (loaded
every boot). Lead Agent pattern matches how the session actually behaves
today. acceptEdits removes ~30% of interrupt prompts in a typical coding
session. All three wins compound.

### Critic
Council veto is the non-negotiable safeguard. The 5 governance agents MUST
be explicit about: (a) what they block, (b) escalation paths, (c) when user
is required. This consensus doc formalizes the council's authority so no
future "optimization" removes it. Architecture_optimizer cannot propose
removing any of the 5 without tier 4 user approval.

## Synthesis — unanimous

All 4 agree. Ship.

## Consensus Council — explicit authority

The 5 governance agents collectively have **ship veto** on:
- New code merged to main/trunk
- New architecture changes
- Constitution / policy amendments
- New agents added to registry
- MCP server changes

Each agent's specific veto power:

| Agent | Vetoes on |
|---|---|
| `critic` | Any output with unaddressed flaws (CRITICAL or HIGH severity) |
| `evaluator` | Any output failing correctness/completeness rubric |
| `security` | Any security-sensitive change (auth, I/O, net, fs, secrets) |
| `reflection` | Any task completing without strategy/experience captured (audit gap) |
| `knowledge_validator` | Any unresolved `AMBIGUOUS` graph edge affecting modified concept |

Escalation: 2× veto on same node → auto-escalate to user (tier 3+).
Override: user explicit tier-4 approval logged as `constitution_amendment`.

## Reopen conditions

- Anthropic deprecates Agent Teams → reopen Lead Agent pattern decision.
- Council false-positive rate > 20% → reopen gate thresholds per governance agent.
- Permission mode `acceptEdits` causes production incident → reopen default choice; may need domain-aware permission policy.
- Constitution grows back past 300 lines → reopen diet (extract again to history.md).
- User discovers Claude Code ships new canonical pattern not yet adopted → normal amendment process.
