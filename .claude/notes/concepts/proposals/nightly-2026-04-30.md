## CLAUDE.md Improvement Patches

### Patch 1: CLAUDE.md size discipline (§3 Core Rules — NI-005)
Add to Rule 4 (narrative writes):
```
- CLAUDE.md files MUST target under 200 lines per file. Files over 200 lines reduce adherence. Use .claude/rules/ path-scoped rules for overflow. HTML comments <!-- ... --> are stripped before context injection — use for maintainer notes that don't cost tokens.
```
Source: https://code.claude.com/docs/en/memory#write-effective-instructions

### Patch 2: Hook lifecycle expansion (§11 Hook Stack — NI-001/002/003)
Current §11 lists 13 scripts / 12 lifecycle events. Expanded hook reference:
```
**Additional hook lifecycle events** (not yet wired in our stack):
- UserPromptSubmit — pre-process user prompts (blockable)
- UserPromptExpansion — slash command expansion
- PermissionRequest — when permission dialog shows
- PermissionDenied — when auto-mode classifier denies
- PostToolBatch — after parallel tool batch resolves
- TaskCreated / TaskCompleted — task management (agent teams)
- TeammateIdle — agent team idle signal
- InstructionsLoaded — CLAUDE.md/rules file loaded (debug hook)
- CwdChanged / FileChanged / WorktreeCreate / WorktreeRemove — filesystem events

**Additional hook handler types** (not yet used in our stack):
- `http` — remote endpoint with auth headers
- `mcp_tool` — call MCP server tool directly
- `prompt` — single-turn Claude eval (fast model)
- `agent` — experimental subagent with tool access

**New hookSpecificOutput fields**:
- `updatedInput` — modify tool input before execution
- `additionalContext` — inject context into Claude's view
- `permissionDecision: "defer"` — defer to external handler (v2.1.89+)
```
Source: https://code.claude.com/docs/en/hooks

### Patch 4: Security layer update (§9 Safety Layers — NI-010)
Add to safety layers section:
```
**External threat landscape** (2026):
- Prompt injection = OWASP LLM Top 10 #1. Current mitigations incomplete; design systems with this assumption.
- MCP tool poisoning: attacker-controlled MCP tools can force credential exfiltration via logging. Our policy_guard + allowedMcpServers mitigate this.
- PALADIN 5-layer defense: input validation → privilege minimization → output filtering → behavioral monitoring → escalation path. Our hook stack + Council approximates this pattern.
```
Source: https://witness.ai/blog/prompt-injection/

## New Hook Patterns Detected

### InstructionsLoaded debug hook
```json
{
  "hooks": {
    "InstructionsLoaded": [
      {
        "type": "command",
        "command": "python .claude/hooks/log_instructions_loaded.py",
        "async": true
      }
    ]
  }
}
```
When fired: each time a CLAUDE.md, CLAUDE.local.md, or rules/*.md file is loaded. Input includes file path and why it loaded (startup/on-demand). Useful for debugging path-scoped rule loading.
Source: https://code.claude.com/docs/en/hooks#instructionsloaded

### UserPromptSubmit security scan hook
```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "type": "command",
        "command": "python .claude/hooks/prompt_injection_scan.py"
      }
    ]
  }
}
```
Exit 2 to block; `hookSpecificOutput.additionalContext` to enrich with threat assessment. Addresses OWASP LLM Top 10 #1 defense.
Source: https://code.claude.com/docs/en/hooks#userpromptsubmit

## New Skill Trigger Improvements

From community analysis, the top improvement to skill descriptions:
- Current: description may be vague → Claude scans 100 tokens/skill and may miss triggers
- Improved pattern: start with "Use when: <specific conditions>" + "Do NOT use for: <anti-cases>"
- Example: our `lead-agent` skill should clarify it is for task entry, not lookup

Skills should distinguish Capability Uplift vs Encoded Preference in their descriptions so Claude can route appropriately.
